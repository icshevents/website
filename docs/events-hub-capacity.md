# Private booking limits per event form

Manage Event Forms → Edit form details & limit controls each form’s private capacity, title/year, date, venue, booking window and existing ticket prices. No allowance is shared across forms. Ticket adults and children each use one place; participation, stall and custom forms count one sign-up per entry. Pending payments reserve places. Verified source failures, expiries, cancellations and refunds release places; workspace review labels and recoverable list deletion do not change payment evidence.

Duplicate a ticket, participation, stall or custom form into the same event workspace for another year. The new form starts unpublished with its own ID, link, entries and CSV. Review its copied date, venue, capacity and prices before publishing. Existing native Iftari bookings retain their original system and have a separately editable limit in the form list.

Saving or republishing the website feature does not overwrite independent form settings. The next upcoming published ticket form supplies the public booking link, dates, venue and ticket prices; the website description, poster and menu remain editable in the website feature. The numerical capacity remains private. Existing authored descriptions are retained verbatim.

At the limit, only that form stops taking new bookings and shows: “We've reached the maximum bookings for this event. Please contact events@icsh.org.uk.” Form submission checks and transaction locks enforce the limit server-side, including stale forms. Increasing a limit or verified release reopens availability. A limit cannot be reduced below that form’s existing bookings/reservations. Existing payment updates, refunds and idempotent response recovery are preserved.

Installation preserves all existing form limits and submissions. It retires shared event capacity enforcement without altering current form configurations. No booking record is copied or changed. New database functions are service-role-only and require the Events Hub token for settings writes. Regression tests cover independent annual 60/40-place forms, closing one form without closing others, past workspace dates, lower-limit rejection, conflicting saves, privacy, separate entries and original native Iftari settings.
